Understanding the Problem
- Support multiple people editing one document while seeing each other's changes and cursor positions.
- Concurrent editing requires an operation-merging model; transmitting whole snapshots is not enough to prevent lost work.

Functional Requirements
- Create and load documents.
- Apply concurrent edits and show updates in real time.
- Display collaborator presence and cursors.

Non-functional Requirements
- Keep typing responsive with local feedback and low-latency propagation.
- Converge to a consistent document despite concurrent edits, retries, and reconnects.
- Persist edits durably and scale connection handling independently from document storage.

Core Entities
- Document stores identity, permissions, and the latest snapshot/version.
- Operation records an edit with client identity, operation ID, and ordering or causal metadata.
- Session tracks an active collaborator; Presence stores ephemeral cursor and availability information.

API
- Create a document and fetch its snapshot plus synchronization position.
- Open an authenticated document collaboration channel and submit operations with stable IDs.
- Receive accepted operations and acknowledgements; reconnect from a known revision or synchronize using the chosen merge protocol.
- Send presence separately from durable document edits because stale cursor updates can be discarded.

High-Level Design


1) Create and load
- Persist metadata and an initial snapshot, enforcing document access on both HTTP requests and persistent connections.
- Load a snapshot and all operations after its position before presenting a fully synchronized document.
- Buffer live events during initial loading or use a boundary token so edits are not missed between snapshot and subscription.

2) Concurrent editing
- Whole-document replacement allows one client's stale snapshot to overwrite another client's work.
- Operational transformation adjusts incoming operations against concurrent edits, commonly with a server-defined order.
- CRDTs encode operations or state so replicas can merge and converge under their defined rules.
- Choose one model and explain its metadata, ordering, and storage costs rather than treating the two approaches as interchangeable boxes.
- Apply edits locally for responsiveness, then reconcile acknowledgements and remote edits using that model.

3) Broadcast and presence
- Route document operations to the collaboration owner or shared document channel and broadcast accepted edits.
- Deduplicate operations by ID; reconnect replay must not insert the same text twice.
- Cursor positions need transformation or stable anchors as text changes around them.
- Expire presence after missed heartbeats; a disconnected collaborator should not remain permanently online.

Deep Dives


1) Connection scaling
- Partition active documents across collaboration servers and route all participants to the appropriate owner or channel.
- Separate persistent connection gateways from durable operation storage when needed.
- A very popular document remains a hot key; limit or specialize its collaboration path rather than assuming more document shards fix it.
- On owner failure, recover from durable state and force clients to resume from acknowledged positions.

2) Bound storage and replay
- An append-only operation log supports recovery but grows indefinitely and makes cold loads slow.
- Periodically create a snapshot at a known log position, then replay only later operations.
- Compact safely: retain what offline clients and the merge algorithm still need, including relevant tombstones or revision history.
- Publish snapshots atomically with their boundary so readers cannot combine a new snapshot with the wrong operation range.

Final Design
- Durable snapshots and an operation log support recovery and history.
- A selected OT or CRDT model defines concurrent edit semantics; collaboration servers deliver its operations in real time.
- Separate ephemeral presence, bounded replay, and authenticated document routing keep the editing experience responsive and recoverable.
