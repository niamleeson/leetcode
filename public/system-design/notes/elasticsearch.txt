Overview
- Elasticsearch provides distributed search and analytics over documents using Lucene indexes.
- It is often a derived search view fed from an authoritative application database, with explicit indexing lag and rebuild procedures.

Basic Concepts
- A document is a JSON record; an index groups documents with related mappings and query behavior.
- Mappings define field types. Text fields are analyzed for search, while keyword fields preserve exact values for filtering and aggregation.
- Configure dates, numbers, nested objects, and geographic fields deliberately; incorrect mappings can make intended queries expensive or impossible.
- Changing a field's fundamental mapping often requires a new index and reindexing.

Basic Use
- Create an index and mapping, then index documents using stable IDs.
- Partial updates still require internal document reindexing; frequent mutable fields can generate substantial write and merge work.
- Use match-style queries for analyzed text and filters for exact constraints that do not need relevance scoring.
- Geospatial queries require the appropriate point or shape mapping and a clear distance or boundary interpretation.
- Sorting by recency or popularity needs sortable fields; relevance ordering uses the search score and explicit tie-breakers where needed.

Pagination and Cursors
- from/size pagination is convenient for shallow pages, but deep offsets make shards gather and discard increasing amounts of data.
- search_after continues after the previous sort values and requires stable sorting with a unique tie-breaker.
- A point-in-time context can stabilize a paginated search while documents change.
- Scroll-style traversal is suited to batch extraction; choose the pagination mechanism for the actual user interaction.

How It Works

1) Nodes and shards
- Primary shards partition the index; replicas provide additional read capacity and failover copies.
- Coordinating nodes route queries to shards and merge bounded results.
- Cluster-management roles coordinate metadata and shard allocation, separate from the document-query work.
- More shards increase parallelism but also coordination, memory, and small-shard overhead.

Process: Execute a distributed search page
- Step 1: The client sends query, filters, sort order, and pagination context to a coordinating node.
- Step 2: The coordinator selects relevant shards and dispatches the query to suitable shard copies.
- Step 3: Each shard uses its indexes to filter and score candidates and returns a bounded local set with sort values.
- Step 4: The coordinator merges those sets and fetches the selected document fields as needed.
- Step 5: It returns the global page and continuation information; point-in-time plus stable sort values preserves the intended context for later pages.

2) Lucene segments
- Lucene writes immutable segments and exposes new data after a refresh, making search near real time rather than immediately consistent by default.
- Updates and deletions create replacement records or deletion markers; background merges reclaim space and consolidate segments.
- Refresh and merge settings trade freshness against indexing throughput and resource cost.

Process: Index an update and make it searchable
- Step 1: The application commits its authoritative change and sends a versioned indexing event to a worker.
- Step 2: The worker submits the document under a stable ID; Elasticsearch routes it to the appropriate primary shard.
- Step 3: The shard applies indexing/translog work and replication according to the configured write and durability settings.
- Step 4: The indexing request is acknowledged when its configured conditions are met; that acknowledgement does not necessarily mean ordinary search can see the change yet.
- Step 5: A refresh makes the new segment state searchable. A caller needing that boundary can use the supported refresh policy instead of assuming immediate visibility.
- Step 6: Background merges later consolidate segments and reclaim eligible obsolete data; they are separate from the refresh that exposed the document.

3) Search data structures
- An inverted index maps terms to document postings, with positions where phrase search requires them.
- Doc values organize field values for efficient sorting and aggregation.
- Query execution should reduce candidates with selective filters before expensive scoring or sorting where possible.
- A hot term or broad query can be costly even when the corpus is evenly sharded.

In Your Interview
- Explain why full-text relevance, geographic filtering, or complex search warrants a specialized engine.
- Keep primary writes and indexing updates connected through a reliable change stream or outbox.
- Version updates and propagate deletions so delayed events cannot restore stale content.
- Recheck permissions when index staleness could expose restricted documents.
- Plan reindexing with aliases or another controlled switchover while concurrent changes continue.

Summary
- Elasticsearch makes search efficient through specialized indexes and distributed execution.
- Its costs are additional storage, eventual search freshness, shard operations, and continuous index maintenance.
- Use it when those tradeoffs solve concrete query requirements rather than as a replacement for every database access.
